Codesuab Laravel Permission

A high-performance, framework-native RBAC and ACL package for Laravel. Features seamless Gate/Policy hooks, Blade directives, Inertia.js React components, first-class Multi-Tenancy/Teams, wildcard permissions, and an interactive ACL Matrix.

$ composer require codesuab/laravel-permission
Get Started

Zero Method Overrides

Uses Permission::ensure() without ever overriding Eloquent's native Model::create().

Tenant & Team Scoped

Assign roles and permissions globally or per tenant/team with automatic middleware context isolation.

Gate & Route Hooks

Automatic Gate::before integration, model table inference, and fluent Route::can() macros.

# Overview & Architecture

Codesuab Laravel Permission is engineered specifically for modern Laravel applications that need enterprise-grade authorization without boilerplate or database overhead. It combines Role-Based Access Control (RBAC) and Access Control Lists (ACL) in a unified, intuitive schema.

Core Architectural Principles

  • Framework Native: Leverages standard Laravel conventions—service providers, Eloquent relationships, Gates, Policies, and Middlewares.
  • Zero Interference: Avoids dangerous magic or polluting Eloquent core methods like create().
  • Contextual Caching: Permissions are cached per-user and per-team with automatic invalidation upon any role or direct permission assignment.
  • Front-to-Back Symmetry: Authorize on the backend with Gate/Route and reflect seamlessly in Blade directives or Inertia React components.

# Installation & Setup

Follow this 4-step installation workflow to install the package, publish configuration, run database migrations, and seed the default super-admin role.

Step 1

Install via Composer

composer require codesuab/laravel-permission
Step 2

Publish Configuration and Migrate Database

Run the interactive installer to publish config/permission.php and execute migrations:

php artisan permission:install

Alternatively, run manually: php artisan vendor:publish --tag=permission-config && php artisan migrate

Step 3

Seed Super-Admin Role

Creates the wildcard permission * and initial active super-admin role:

php artisan permission:seed
Step 4

Attach Traits to User Model

Add HasPermissions and optionally HasTeams to your Authenticatable model (usually App\Models\User):

namespace App\Models;

use Illuminate\Foundation\Auth\User as Authenticatable;
use Codesuab\Permission\Traits\HasPermissions;
use Codesuab\Permission\Traits\HasTeams;

class User extends Authenticatable
{
    use HasPermissions, HasTeams;

    // ...
}

# User Model & Traits API

The HasPermissions trait equips your User model with a full suite of fluent role and permission management methods.

Method Parameters Description
assignRole() string|array $roles, $teamId = null Assigns one or multiple roles (attaches without detaching existing).
syncRoles() array $roles, $teamId = null Replaces all user roles with the provided list.
removeRole() string|array $roles, $teamId = null Detaches specified roles from the user.
hasRole() string $role Checks if user possesses the specified role.
hasAnyRole() array $roles Returns true if user has at least one role in list.
givePermissionTo() string|array $permissions, $teamId = null Assigns direct permissions directly to user without roles.
revokePermissionTo() string|array $permissions, $teamId = null Revokes direct permissions from user.
hasPermission() string $permission Checks if user has permission via roles or direct grants.
hasAnyPermission() array $permissions Checks if user matches any of the given permissions.
hasAllPermissions() array $permissions Checks if user satisfies every permission in list.
permissionSlugs() void Returns array of all permission slugs available to user.
isSuperAdmin() void Returns true if user has configured super admin role.

# Permissions & Roles Deep Dive

Design Notice: Always use Permission::ensure() rather than creating records manually. ensure() formats the slug, sets a humanized title, extracts the group prefix, and avoids overriding Eloquent's native Model::create(). 
use Codesuab\Permission\Models\Permission;
use Codesuab\Permission\Models\Role;

// 1. Ensure permissions exist (idempotent firstOrCreate)
Permission::ensure('users.view');
Permission::ensureMany(['users.create', 'users.update', 'users.delete']);

// 2. Generate standard resource CRUD permissions
// Returns ['view' => 'users.view', 'create' => 'users.create', 'update' => 'users.update', 'delete' => 'users.delete']
$crud = Permission::crud('users');

// 3. Create a Role and attach permissions
$manager = Role::createRole('manager');
$manager->allow([
    'users.view',
    'users.create',
    'users.update',
]);

// 4. Revoke or sync permissions on role
$manager->deny('users.update');
$manager->syncPermissions(['users.view', 'reports.export']);

// 5. Assign to User
$user->assignRole('manager');
$user->givePermissionTo('special.audit'); // direct grant

// 6. Inspect access
if ($user->hasPermission('users.view')) {
    // User is authorized
}

# Wildcard Permissions

Codesuab Laravel Permission features native wildcard matching with dot-notation. You can grant wildcards to entire domains or submodules without defining every individual action.

* Global Wildcard

Grants unconditional access to all abilities across the entire application.

Role::createRole('root')->allow('*');

users.* Domain Wildcard

Matches any action under users (e.g. users.view, users.delete, etc.).

Role::createRole('admin')->allow('users.*');
Under the Hood: Regex Compilation

Permissions containing * or ? are escaped safely with preg_quote and translated to .* and . regex patterns, ensuring deterministic evaluation without ReDoS vulnerability.

# Super Admin Bypass

Applications frequently require a master administrative role that bypasses all permission checks without needing individual grants. Configure this in config/permission.php: 

'super_admin' => [
    'enabled' => true,
    'role'    => 'super-admin',
],

When enabled, any user possessing the active super-admin role automatically evaluates to true on all hasPermission(), Gate::allows(), and middleware checks without additional database queries.

# Route Macros & Middleware

Codesuab Laravel Permission automatically registers expressive macros on Laravel's Route facade, letting you protect endpoints with clean syntax. 

use Illuminate\Support\Facades\Route;

// Single or multiple permissions (OR check - user needs ANY of these)
Route::get('/users', [UserController::class, 'index'])->can('users.view');
Route::get('/analytics', [AnalyticsController::class, 'show'])->can('analytics.view', 'reports.view');

// Multiple permissions (AND check - user needs ALL of these)
Route::get('/export', [ExportController::class, 'run'])->canAll('reports.view', 'reports.export');

// Role-based protection
Route::get('/admin/panel', [AdminController::class, 'index'])->role('admin');
Route::get('/finance/settings', [FinanceController::class, 'edit'])->roleAll('admin', 'finance-lead');

// Team-aware route macro
Route::team('team')->group(function () {
    Route::get('/teams/{team}/dashboard', [TeamDashboardController::class, 'show']);
});

Available Middleware Aliases

Middleware Alias Class Name Behavior
permission:perm1,perm2 PermissionMiddleware Requires any of the listed permissions (OR).
permission.all:perm1,perm2 PermissionAllMiddleware Requires all listed permissions (AND).
role:role1,role2 RoleMiddleware Requires any of the specified roles (OR).
role.all:role1,role2 RoleAllMiddleware Requires all specified roles (AND).
permission.resource:name ResourcePermissionMiddleware Maps resource actions automatically to CRUD permissions.
permission.team TeamMiddleware Extracts team ID, checks user membership, sets request context.

# Resource Controller Protection

Instead of writing authorization boilerplate in every controller action, simply chain can('resource') to your Route::resource() declaration: 

Route::resource('users', UserController::class)->can('users');

# Gate & Policy Integration

Codesuab Laravel Permission registers a Gate::before callback during boot. This provides seamless, non-intrusive interoperability with native Laravel authorization methods: 

// 1. Direct permission checks with Gate & authorize
Gate::allows('users.update');
$this->authorize('users.update');

// 2. Eloquent Model Policy inference
// If you authorize a Model instance, the package derives the resource name from $model->getTable()
$post = Post::find(1);
$this->authorize('update', $post); // Checks 'posts.update'
$this->authorize('view', $post);   // Checks 'posts.view'
$this->authorize('delete', $post); // Checks 'posts.delete'

Custom Model-to-Resource Mapping

If a model's table name does not match the desired permission slug prefix, define an explicit mapping in config/permission.php:

'policies' => [
    'map' => [
        App\Models\Invoice::class => 'billing.invoices',
    ],
],

Now $this->authorize('update', $invoice) checks billing.invoices.update automatically.

Fallback guarantee: If the package does not explicitly grant the ability, the Gate::before hook returns null, allowing execution to proceed down to your custom Laravel Policy classes without obstruction.

# Multi-Tenancy & Teams

Enterprise apps often require multi-tenant permissions: a user might be a manager in Team Alpha, but an editor in Team Beta. 

use Codesuab\Permission\Models\Team;

// 1. Create a Team and attach members
$team = Team::createTeam('Acme Corp', ownerId: $owner->id);
$owner->addToTeam($team);
$user->addToTeam($team);

// 2. Assign role within specific team scope
$user->assignRole('manager', teamId: $team->id);

// 3. Grant direct permission within team scope
$user->givePermissionTo('invoices.refund', teamId: $team->id);

// 4. Check permissions within team context
app('permission')->team($team->id)->check($user, 'invoices.refund'); // returns true
team_permission($team->id, 'invoices.refund'); // via helper

Team Routing Middleware

Protect tenant routes by wrapping them with the permission.team middleware: 

Route::middleware('permission.team')->group(function () {
    Route::resource('/teams/{team}/projects', TeamProjectController::class)->can('projects');
});
Lifecycle & Safety:
  • Middleware resolves {team} from the route parameters (model or integer ID).
  • When require_membership => true, unauthenticated requests abort 401, and non-members abort 403.
  • Sets TeamContext for the active request and clears it safely inside a finally block.
  • When global_permissions => true, permissions granted without a team ID remain valid across all teams.

# ACL Matrix API & React UI

Build role-permission management matrices with zero manual pivot querying. The AclMatrix service exports a structured matrix and syncs updates cleanly. 

use Codesuab\Permission\Support\AclMatrix;

// 1. Build matrix data for an administrative panel (or tenant)
$matrixData = app(AclMatrix::class)->build($teamId = null);

// Returns structure:
// [
//   'roles' => [['id' => 1, 'name' => 'Admin', 'slug' => 'admin'], ...],
//   'permissions' => [['id' => 1, 'name' => 'Users View', 'slug' => 'users.view', 'group' => 'users'], ...],
//   'matrix' => [
//       'admin' => ['users.view', 'users.create', 'users.*'],
//       'manager' => ['users.view'],
//   ]
// ]

// 2. Sync all permissions for a role
app(AclMatrix::class)->sync($role, ['users.view', 'users.create'], $teamId);

// 3. Toggle a single permission
app(AclMatrix::class)->set($role, 'users.delete', allowed: true, teamId: $teamId);

# Blade Directives

Codesuab Laravel Permission ships with pre-compiled Blade directives that conditionally render blocks based on the authenticated user's authorization state. 

{{-- Single permission check --}}
@permission('users.create')
    <button class="btn">Create User</button>
@endpermission

{{-- Any permission check (OR) --}}
@anypermission('users.edit', 'users.update')
    <a href="/users/edit">Edit User</a>
@endanypermission

{{-- All permissions check (AND) --}}
@allpermissions('reports.view', 'reports.export')
    <button>Export Financial Summary</button>
@endallpermissions

{{-- Single role check --}}
@role('admin')
    <div>Welcome to Super Admin Console</div>
@endrole

{{-- Any role check (OR) --}}
@anyrole('admin', 'manager')
    <div>Management Dashboard</div>
@endanyrole

{{-- All roles check (AND) --}}
@allroles('admin', 'security-officer')
    <div>System Audit Logs</div>
@endallroles

# Inertia.js React Adapter

When Inertia is detected, the package automatically shares auth.permissions, auth.roles, and active auth.team with the frontend on every request.

React Components & Hook Usage

import React from 'react';
import { 
    Can, 
    CanAny, 
    CanAll, 
    Role, 
    usePermissions,
    filterByPermission 
} from '@codesuab/laravel-permission';

export function Navigation() {
    const { can, canAny, hasRole, permissions, roles, teamId } = usePermissions();

    return (
        <nav>
            {/* Conditional component rendering */}
            <Can permission="users.create" fallback={<span>Upgrade to Invite Users</span>}>
                <button>Invite User</button>
            </Can>

            <CanAny permissions={['reports.view', 'analytics.view']}>
                <a href="/insights">Insights</a>
            </CanAny>

            <Role role="admin">
                <a href="/admin">Admin Console</a>
            </Role>

            {/* Direct hook checks */}
            {can('invoices.refund') && <button>Issue Refund</button>}
        </nav>
    );
}

// Filter dynamic navigation arrays safely
const navItems = [
    { title: 'Dashboard', href: '/dashboard' },
    { title: 'Users', href: '/users', permission: 'users.view' },
    { title: 'Billing', href: '/billing', role: 'finance' },
];

const visibleItems = filterByPermission(navItems, can, hasRole);
Crucial Security Notice: Client-side React checks are strictly UI helpers for conditional rendering and user experience. Never rely on frontend checks as a security boundary. Always enforce authorization on the backend via Laravel Middleware, Gates, and Policies!

# Artisan CLI Commands

Codesuab Laravel Permission bundles several purpose-built Artisan commands for setup, maintenance, and route discovery.

permission:install {--force} Setup

Publishes the permission-config tag and runs database migrations. 

php artisan permission:install
permission:seed Seeding

Creates the wildcard permission * and sets up the active system super-admin role.

php artisan permission:seed
permission:make {resources*} {--crud} Scaffolding

Creates permissions on the fly. Passing --crud expands each resource into view, create, update, and delete actions.

# Generate CRUD permissions for users and products
php artisan permission:make users products --crud

# Output:
# ✓ users.view
# ✓ users.create
# ✓ users.update
# ✓ users.delete
# ✓ products.view
# ...
permission:sync-routes Introspection

Inspects registered resource routes in your Laravel application and automatically ensures corresponding CRUD permissions exist in the database.

php artisan permission:sync-routes

# Caching & Invalidation Architecture

Permission lookups are cached automatically to prevent N+1 query overhead. The cache key separates user identifiers and team context: 

{prefix}:user:{user_id}:team:{team_id|global}
Example: codesuab.permission:user:42:team:5

Automatic Cache Invalidation

Whenever any of the following events occur, cache entries are invalidated automatically without manual intervention:

  • Assigning, detaching, or syncing roles on a User (clear($user)).
  • Granting, revoking, or syncing direct permissions on a User (clear($user)).
  • Updating role permissions via $role->allow() or $role->syncPermissions() clears all users holding that role.
  • ACL Matrix updates trigger automatic user cache clearing.
Manual Cache Clearing:
// Clear specific user
app('permission')->clear($user);

// Clear all users holding a role
app('permission')->clearRole($role);
